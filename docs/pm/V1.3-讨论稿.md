## 一、候选游戏模式清单与取舍（结论）

### 1.1 调研覆盖

- 中文：聚会玩（谁是卧底/天黑请闭眼/一愚惊人/吹牛/射鸡）、联玩（谁是卧底/你演我猜/害你在心口难开/关键词唱歌/眼色游戏/搞怪惩罚）、聚会嗨（转盘/旋转瓶子/你画我猜/大话骰）、国王游戏类小程序/KingsBot、国王游戏 2026 高阶版（动态难度/免死金牌/国王宪章/熔断机制）。
- 外文：Picolo（prompt-led 多包）、SPILL（30+ modes、intensity ramp、双周上新）、WOOZE（Would You Rather / Virus / Round the Table / Where is Peanut / Drawing / RPS）、Game of Shots MAX（board + roulette + Spin the Bottle）、Heads Up!（额头猜词/倾斜操作）、Psych!（bluff trivia）、DrinkCountr/Drinkster/Drink Roulette（轮盘/主题包/自定义题）。
- 综合论文侧（仅取可落地结论）：跨 batch 重复是普遍现象（cross-batch mode collapse），去重 + prompt 引导需组合使用，单次大 batch 易塌缩，embedding 去重阈值约 0.85–0.92，few-shot 示例是转向关键。

### 1.2 结论：建议引入（按优先级）

| 排序 | 候选模式 | 一句话玩法 | 与现有差异 | 引入理由 |
|---|---|---|---|---|
| 1 | 国王游戏·安全版（King 安全版） | 抽签定国王发指令，被点名者执行/可用免死币否决一次 | 现有 4 个都是“抽卡答题”，缺“权力+点名”结构；酒吧拼桌破冰最强 | 单设备可实现，复用 player-selector 公平性 + Boundary 强约束 + 无惩罚跳过；天然适配人数/关系/强度条件 |
| 2 | 你演我猜 · Heads Up 式 | 一人表演/描述，全桌猜词，计时 60s，可跳过 | 现有缺肢体/表演类，高噪声酒吧环境反而好用 | 无需联机，单设备计时+翻牌即可；与 ai-improv 互补（一个语言即兴，一个肢体竞猜）；boundary 风险低 |
| 3 | 二选一 · Would You Rather / 快问快答 | 给两难选项，全桌站队/投票，附带追问 | 现有投票类只有“谁最可能”（指人），缺“观点站队”（指事）；开局破冰更快 | 纯文本卡，Engine 零改动即可接入；适合 2 人局和 9+ 大局；强度可控 |

### 1.3 备选（可二选一，不建议一次全做）

| 候选 | 取舍结论 |
|---|---|
| 歌曲挑战（关键词唱歌/歌词接龙） | 酒吧/KTV 场景贴合度最高，但涉及曲库与版权/离线问题。建议作为“AI 即兴”的子题型先验证，不单独成 Pack。若用户明确要，再独立成包。 |
| 病毒规则 · Virus / 害你在心口难开（整局 sticky rule，如“不许说你/我”） | 趣味性强、实现成本低（一条 session 级规则+触发判定），但会改变 Engine 状态机。建议先做 1 条 MVP 规则验证，再决定是否成 Pack。 |
| 谁是卧底轻量版（单机发牌+口述投票） | 中文市场需求大，但完整卧底/狼人杀依赖隐藏身份+多轮发言，单设备体验打折且主持负担重。若做只做“3–6 人轻量发牌器”，不做在线房间。 |

### 1.4 明确不建议（结论 + 理由）

- 完整狼人杀/天黑请闭眼：需法官+夜晚流程+多身份 ocult，单机主持成本高，违背“20 秒开局、低操作负担”（Constitution §II）。
- 多人实时房间/联机/Discord Bot 式：明确 Out of Scope（SPEC §8），V1.3 不碰。
- 转瓶子/骰子/轮盘单独成 Pack：应做成 Engine 通用随机表现层，而非内容 Pack，避免 Pack 爆炸。
- 绘画（你画我猜完整版）：需画布+识别/展示链，酒吧暗光+单设备体验差，投入产出比低；可先用“口述绘画题”在即兴包内覆盖。
- 强制喝酒/Caliente 成人越界/羞辱式惩罚：违反 Boundary-by-Design（Constitution §IV），不引入。（注：`noAlcoholPenalty=true` 硬性默认已于 2026-09-21 由用户拍板删除，酒罚默认含、可在雷区关闭；本条仅指强制/越界/羞辱类，不溯及普通酒罚。）
- Psych! 式 bluff trivia / 长推理答题：在酒吧注意力碎片场景太重，且题库维护成本高。

> 落到 V1.3 建议：新增 Pack 不超过 2 个（国王安全版 + 你演我猜），二选一可先以真心话/谁最可能的子类型进入，避免一次扩 4–5 个包导致 Deck 稀释与测试爆炸。

## 二、AI 整局预生成重复问题：诊断与去重/差异化机制（结论）

### 2.1 现状诊断（基于当前代码事实）

1. `prompt-builder.ts` 为单 prompt 一次要 40 张：无分包配额、无强度直方图要求、无 participantMode 配额、无随机 nonce/seed、无历史 ban-list，模型易走高频套话。
2. `generate-deck.ts:buildPlayableDeck` 顺序为 AI→custom→seeds 后 `slice(0,target)`：AI 填满时 seed 多样性被截掉；AI 不足时才靠 seed 补齐，无二次带排除名单重试。
3. `normalize.ts:dedupeCards` 仅做 `packId + 去标点小写` 精确去重：能抓逐字重复，抓不住改写/近义重复（如“我从来没有熬夜” vs “我从没熬过夜”）。
4. 无语义去重层：无 embedding/Jaccard/shingle 相似度 gate，无 intra-deck 相似度指标。
5. 无跨局记忆：上局出过的题下局可再出；`preferences-repository` 未存指纹历史（local-first 下本可存，但现状无）。
6. 条件未进入生成：人数仅在过滤阶段用 `minPlayers/maxPlayers` 拦截，prompt 未按 2 人/3–5/6–8/9+ 差异化 participantMode 分布；难度仅传“最高强度”，未要求 1–5 分布。

### 2.2 机制目标（结论）

- 同局 0 无意重复（沿用 SC-003），近义重复显著下降。
- 不同配置（人数×关系×氛围×强度）生成可感知差异，而非同一套万能题。
- 仍满足：整局预生成、离线可玩、失败可回退 seed、Key local-only、无云端记忆外泄。

### 2.3 建议机制（结论，分 4 层，均可在现有 Engine/GamePack 解耦下做）

**A. Prompt 分包 + 配额（最先做，成本最低）**

- 将 40 张拆 4 个子请求或 1 请求内强制分节：按 `enabledPackIds` 配额（如混合默认 30/25/25/20，可按 Stage 微调，见 PLAN §8.1）。
- prompt 强制要求：intensity 直方图（例如强度上限 3 时 1:2:3 ≈ 40/40/20；上限 5 才允许 4–5 且占比封顶）、participantMode 分布按人数表（2 人局禁 all-指人题；9+ 提高 all/pair 占比）。
- 每次 prompt 注入：`sessionNonce`（随机串）+ 关系/氛围定制约束各 1 句 + “已见 ban-list（本局已产出指纹前 N 条）不得输出”。
- VTS-lite：要求模型对每卡自评 `obviousness 0–1`，>0.7 的题要求自我替换（不增加外部依赖，纯 prompt 约束）。

**B. 管道三层过滤（规则先行，embedding 后议）**

1. L1 精确去重（保留现有 `dedupeCards`）。
2. L2 轻量近义去重（建议 V1.3 做）：shingle Jaccard + 关键词重叠（如 2-gram Jaccard >0.75 判重），零依赖、可单元测试、无隐私外发。
3. L3 语义去重（待决策，见三.4）：on-device embedding 或 server-side 可选开启；默认关闭以保包体与离线能力。
- 顺序改为：AI→去重→按配额缺口二次生成（带 exclude-list）→custom→seeds 补齐→最终 slice。不足阈值（如 <10 即 `INSUFFICIENT_CARDS`）触发一次带 ban-list 的补充生成，而非直接用 seed 掩盖。

**C. 人数×难度条件矩阵（差异化核心）**

| 人数 | participantMode 建议分布 | 备注 |
|---|---|---|
| 2 人 | single/pair 为主，禁“所有人同时指”类（沿用 Edge Case） | 情侣/暧昧关系时提高 truth 占比 |
| 3–5 | single 50 / all 30 / pair 20 | 通用默认 |
| 6–8 | all 40 / single 35 / pair 25 | 强化“谁最可能”类全桌投票 |
| 9+ | all 50 / pair 25 / single 25 | 避免连续点同一人（复用 player-selector 公平性） |

- 强度：只传上限不够，需传“目标直方图”；Stage Warm-up/Flow/Heat-up 只调权重不破上限（沿用 PLAN §7.3）。
- 关系/氛围：拼桌/第一次见强制降低 4–5 权重并禁用暧昧标签子集；放开玩才放开上限（仍受雷区限制）。

**D. 跨局记忆（local-only）**

- 在 IndexedDB（preferences 或新 `deckHistory` store，待定）存近 N 局（如 3 局×40 条）指纹哈希（hash + packId，不存原文亦可），下次生成 prompt 带“avoid list（哈希对应原文前 N 条摘要）”。
- 不上传云端、不进入日志，符合 local-first；用户可在设置一键清除历史（与 Danger Zone 风格一致，但为普通操作）。

**E. 指标（QA 可测）**

- 同局精确重复率 = 0；L2 近义重复率目标 <5%（阈值待调）。
- pack 覆盖率：启用包每包至少占比下限（如 ≥15%）；intensity 越界 = 0；人数不适配 = 0。
- 跨局差异：连续两局同配置的 L2 重复率目标 <15%（初值，待实测校准）。
