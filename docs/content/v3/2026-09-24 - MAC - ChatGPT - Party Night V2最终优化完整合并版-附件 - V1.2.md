# Party Night V2｜00 总览与统一规则（最终优化版）

## 一、产品目标

Party Night 的主线不是“随机播放 350 张题”，而是让 4～5 人酒吧聚会中的男女关系自然经过：

**破冰 → 注意 → 了解 → 好感试探 → 暧昧 → 双向确认 → 愿意继续认识**

软件负责制造机会、提供第三方借口、控制节奏；**不替玩家决定关系，也不把拒绝设计成失败。**

主线题库：7 种游戏 × 50 张 = **350 张**。`08-扩圈模式.md` 为独立可选的 40 张模块，不计入主线。

### 使用边界

- 当前 V2 按成年人聚会设计；应用本身不要求饮酒。
- 明显醉酒、意识不清或无法稳定表达意愿时，停止 4～5 档、近距离与身体接触任务，切回低档或结束游戏。
- 跳过永远合法：不罚酒、不扣分、不要求解释、不公开是谁拒绝。

---

## 二、7 种游戏各自只干一件事

| 游戏 | 核心职责 | 主要关系产出 |
|---|---|---|
| 真心话 | 暴露自己的真实判断 | “原来你是这么看我的” |
| 大冒险 | 把语言变成行动、眼神和距离变化 | “我们真的靠近了一点” |
| 谁最可能 | 借全桌视角发现关系信号 | “原来大家也注意到了” |
| 我从来没有 | 发现共同经历与相似行为模式 | “原来你也这样” |
| 二选一 | 快速扫描社交 / 恋爱偏好 | “我们的选择很像 / 很不一样” |
| 指人游戏 | 当前玩家公开做个人选择 | “TA居然选了我” |
| 默契测试 | 验证特定两人的真实合拍度 | “我居然猜中了你” |

**审题最高规则：**一张题如果主要完成的是另一种游戏的职责，应迁移或重写。

---

## 三、三个概念必须分开：开放度、整桌热度、双人解锁

### 1. Intensity / 开放度：玩家设置的上限

| 档位 | 关系含义 |
|---|---|
| 1 | 注意：开始真正看到对方 |
| 2 | 了解：开始知道对方是什么样的人 |
| 3 | 好感试探：开始让对方知道“我怎么看你” |
| 4 | 暧昧 / 高关系暴露：公开选择、关系判断或明显试探 |
| 5 | 双向确认：需要更明确的双方意愿才能继续 |

档位衡量的是**关系暴露 / 推进程度**，不是身体接触强度。

### 2. Session Heat：整桌当前玩热到哪里，只到 H1～H4

固定总轮数时：

| 进度 | Heat | 内容 |
|---:|---:|---|
| 0～20% | H1 | 破冰、注意 |
| 20～40% | H2 | 了解、共同点 |
| 40～65% | H3 | 主动选择、好感信号 |
| 65～100% | H4 | 明显暧昧、关系试探 |

未设置总轮数时：H1=0～3张，H2=4～7张，H3=8～12张，H4=13张以后。

### 3. Pair Unlock：5档属于具体两个人，不属于整桌

- `matchRequired=true`：只有该 pair 已形成 MATCH 才能进入候选池。
- 一次性双方同意不使用不存在的 `privateMutualRequired` 字段；统一用 `consentMode=private-mutual-only` + `signalEffects=one-off-mutual` 表达，并且只对当轮有效。
- 某一 pair 解锁5档，不代表其他 pair 同时解锁。

---

## 四、Coverage Gate：先确保每个人都参与，再升温

### 什么叫“合格异性互动”

同时满足下面条件才计 1 次：

1. `targetMode` 属于 `system-opposite-sex / choose-opposite-sex / system-pair / signal-pair / match-pair`；
2. 题目实际完成了应答或动作；
3. 不是跳过；
4. 全桌投票、普通二选一、纯聚合统计不算定向互动。

### H1～H2 的最低调度要求

- 定向题占比不得低于 **40%**。
- 最多连续 2 张全桌题；第 3 张必须优先给定向互动。
- 在数学上可行时，进入 H3 前每位活跃玩家至少完成 1 次合格异性互动。
- 进入 H4 前，任何人的合格互动次数不应落后全桌中位数超过 1；否则先做低曝光补偿。

男女数量不均衡时按“可获得的合格对象机会数”归一化，不要求绝对相同次数。

---

## 五、五类关系信号不能混为一谈

1. **Shared**：共同经历。只统计“做过”的少数共同经历；≥80%都做过不加分；“都没做过”不算。
2. **Compatibility**：偏好 / 默契相似。≥80%共识题、跳过题不计；至少共同回答3道有效题才加权。二选一 #41/#42/#50 的私密答案不参与累计。
3. **Crowd**：全桌对某一 pair 的观察。只有“谁最可能”4档 Pair Vote 产生；不能形成 MATCH。
4. **Personal**：玩家自己公开选择某个异性。单向结果不代表对方也有兴趣。
5. **Mutual / MATCH**：双方分别秘密选择彼此，才形成。

眼神、笑、靠近、模仿等行为**不能自动推断成好感或 MATCH**。

---

## 六、秘密互选与 MATCH：改成系统级硬流程，不再靠终局卡碰运气

### 第一次秘密互选什么时候出现

满足以下条件后触发系统事件 `SYSTEM_MUTUAL_CHECK`：

- 至少完成 **9 张有效卡**；
- 已进入 H3；
- Coverage Gate 已通过。

系统逐个私密询问：

> “今晚到现在，你最想继续了解哪位异性？”

选项：一位当前可选异性 / 暂时没有。

### 后续还会不会再问

- 距离上一次秘密互选至少再完成 **5 张有效卡**，才可再次触发。
- 一局最多 3 次常规秘密互选。
- 如果上次之后出现新的 Personal Signal，优先考虑再次触发。
- Session 结束时始终执行一次最终互选复核；不要求前面的终局卡一定被随机抽中。

### MATCH 怎么生成

- A→D 且 D→A：创建 `MATCH(A,D)`。
- 单向选择：不公开、不起哄，计算完立即删除。
- MATCH 只表示双方愿意继续了解，不是恋爱关系标签，也不是任何身体接触许可。

### MATCH 后如何确保5档真的玩得到

若玩家开放度=5，新 MATCH 形成后：

- 该 pair 的5档卡立即进入候选池；
- 在这对人的**接下来2次合格双人出场机会内**，至少优先安排1张合法5档卡；
- 仍受跳过、当前同意、全桌公平与 cooldown 限制。

这样5档不再依赖 #50 终局卡才有机会出现。

---

## 七、终局卡与“谁最可能”终局加赛

### #50 终局卡

- #50 是 milestone card，不是唯一的 MATCH 入口。
- Session 最后25%时提高其优先级，但**不强迫一局把7张终局卡全部跑完**。
- Session 真正结束时由系统统一跑最终秘密互选，因此不会因为随机抽不到 #50 而丢掉收尾。

### `PN-MOST-050` 的一次性双人加赛

全桌 Pair Vote 选出一对后：

1. 分别私密询问这两个人：“愿意多玩一张双人加赛吗？”
2. 双方都愿意：只解锁 **1 张**额外双人卡。
3. 该加赛最高4档、`matchRequired=false`，且排除身体接触 / 近距离 / 拍照录像类卡。
4. 它只是一轮 `one-off mutual unlock`，**不创建 MATCH**。
5. 任一方不愿意：当作无事发生，继续游戏；单边答案立即删除。

这样群众起哄只能制造一次机会，不能越权把两个人推进真正5档。

---

## 八、Pair Engine：先公平，再参考真实信号

`Routing Score = Coverage Score + Signal Bonus - Cooldown Penalty`

它只是“下一轮安排优先级”，**不是爱情概率**。

### 常规权重（可调参）

| 项目 | 权重 |
|---|---:|
| 从未互动过 | +3 |
| 当前玩家曝光明显偏低 | +2 |
| Shared | +0.5 / 次，单pair封顶+1 |
| Compatibility | +0.5 / 次，单pair封顶+1 |
| Crowd | +1 / 次，单pair封顶+2 |
| Personal | +2，封顶+2 |
| MATCH | +5 |
| 上一轮刚配过 | -4 |
| 连续两轮同一对 | -10 |

默认 `Pair Cooldown = 2`。

### 4～5人小局必须自动降权

当当前可用异性 pair 数 ≤6：

- Personal 改为 +1（封顶+1）；
- MATCH 改为 +3；
- Crowd 每次 +0.5（封顶+1）；
- Shared / Compatibility 维持轻权重；
- MATCH pair 也不能绕过 cooldown。

目标：防止一个 MATCH 出现后，后半场几乎只剩这一对在玩。

---

## 九、抽卡规则与 heatMax 硬边界

V1 的 `INTENSITY_WEIGHT = 1 / 2 / 4 / 8 / 16` 作废。

V2 顺序：开放度 → Session Heat → 目标对象 → 逐卡元数据过滤 → Coverage/Cooldown → 合法卡中随机。

### heatMin / heatMax 不再是冗余字段

- 1档：`heatMin=1, heatMax=2`，H3以后硬性退出候选池。
- 2档：`heatMin=2, heatMax=3`，H4退出候选池。
- 3档：`heatMin=3, heatMax=4`。
- 4档：`heatMin=4, heatMax=4`。
- 5档：`heatMin=4, heatMax=4`，同时还必须满足 pair 解锁条件。

因此后半场不会靠“软概率”大量抽回破冰题。

---

## 十、同意与拒绝统一规则

1. 任意玩家随时可跳过；不罚酒、不扣分、不解释。
2. 身体接触、移动座位到对方身边、持续对视、进入更近谈话距离、拍照/视频，都必须当前再次确认。
3. 同意牵手不等于同意拥抱；已同意也可随时停止。
4. 拒绝后不得换成“轻一点再问一次”的连续施压。
5. MATCH 不是任何身体接触默认许可。
6. 双方秘密选择动作时只执行交集；无交集就跳过，不自动替换另一个动作。

## 十一、逐卡数据与隐私

主线逐卡元数据：`10-卡片元数据.json`（schema 2.2）。
扩圈逐卡元数据：`10b-扩圈元数据.json`。

隐私默认：

- Session 结束清空关系图、秘密答案和 MATCH；
- 默认不上传 Pair Signal / MATCH / 私密答案到第三方分析。

## 十三、扩圈模式

- 默认关闭；开放度3～5才可见。
- 不计入 MATCH、Pair Score 或主线关系阶段。
- 不要求陌生人身体接触，不索取联系方式，不要求饮酒。
- 对方拒绝或场景不合适：立即执行本桌 fallback，不二次邀请。
- 40张逐卡规则见 `10b-扩圈元数据.json`。

---

## 十四、最终产品循环

**公平破冰** → **共同经历 / 偏好发现** → **主动选择** → **全桌观察** → **系统级秘密互选** → **MATCH** → **该 pair 解锁5档** → **每个具体动作再次确认** → **双方自己决定是否继续认识**

最终原则：

> **软件制造机会，但不替任何人做决定；算法提高相遇机会，但不制造假的好感。**

# Party Night V2｜00 总览与统一规则（最终优化·大白话版）

## 先记住一句话

**Party Night 不是随机抽题，也不是替人撮合。它是先让所有人都有机会认识，再把真正出现的共同点和好感慢慢放大。**

## 1. 一局游戏应该怎么发展

开场不要猛。先让不同男女组合都说上话、做点轻互动；熟一点以后再出现“我选谁”“大家觉得谁和谁有火花”；等到双方真的秘密互选成功，才给这两个人开放5档内容。

简单说就是：

**先公平认识 → 再发现火花 → 最后只放大真的火花。**

## 2. 1～5档怎么理解

- 1档：注意到你。
- 2档：开始了解你。
- 3档：我开始释放一点“我对你有兴趣”的信号。
- 4档：明显暧昧、公开选择、关系试探。
- 5档：必须两个人都有明确意愿以后才能进入。

玩家开局选5档，只是说“今晚最高愿意玩到5”，**不是第一题就来5档**。

## 3. 整桌只会升温到第4阶段

整桌从 H1 慢慢到 H4。第5档不是“全桌升级”，而是某一对男女单独解锁。

比如 A 和 D 互相选中了，但 B、C 没有，那么只有 A+D 能玩他们的5档题。

## 4. 系统先照顾没怎么玩到的人

前半场优先让不同组合都互动。系统不能总让最外向的两个人反复出场。

什么叫一次有效互动？大白话就是：**系统真的把两个人放进同一道定向题里，而且这道题没有跳过，确实答了或做了。**

H1～H2 至少40%的题应该是这种定向题，而且最多连续两张“全桌一起答”；再往后就要插入一张两人定向互动。

## 5. 系统怎么看“这两个人可能值得再玩一次”

从弱到强大概是：

1. 两个人有共同经历。
2. 两个人很多偏好一样。
3. 全桌都觉得他们有点默契。
4. 其中一个人自己主动选了另一个。
5. 两个人秘密互相选中了——这才叫 MATCH。

前四种都不能当作“双方喜欢”。

## 6. 现在 MATCH 不再靠最后一题碰运气

这是这次最重要的优化。

以前有个问题：很多5档题必须先 MATCH，但 MATCH 又主要靠第50题，可能整局都抽不到，于是5档几乎玩不到。

现在改成系统自己在合适的时候弹出一次秘密互选。

默认规则：

- 玩完至少9张有效题；
- 已经进入第3阶段；
- 大家基本都已经有过至少一次定向互动；

系统就会私下一个个问：

> “今晚到现在，你最想继续了解哪位异性？”

可以选一个人，也可以选“暂时没有”。

如果 A 选 D，同时 D 也选 A：

**❤️ A + D MATCH。**

如果只有 A 选 D：什么都不公开，系统算完就删掉。

## 7. 一局可以问几次秘密互选

不是只问一次，也不能老问。

- 第一次大约在第9张有效题之后。
- 再玩至少5张有效题，才可以再问一次。
- 常规最多3次。
- 游戏结束时一定还有一次最后复核。

所以即使第50题一直没抽到，也不会错过 MATCH。

## 8. MATCH以后，5档要真的有机会出现

如果用户开放度选了5，某两个人刚 MATCH：

系统会在这两个人接下来的两次合适出场机会里，优先给至少一张5档题。

这样“互选成功 → 解锁专属内容”会真的发生，而不是只存在文档里。

但仍然要照顾全桌公平，不能从此所有题都只给这一对。

## 9. MATCH不等于可以碰对方

MATCH只代表：

> “我们现在都愿意继续了解彼此。”

牵手、拥抱、靠近、坐到旁边、持续对视、拍照等，**每一次都重新问双方愿不愿意**。

一个人不愿意就直接跳过，不罚、不追问、不公布是谁拒绝。

## 10. 为什么“谁最可能”的结果不能直接把两个人推进5档

因为“全桌觉得你们有火花”只是别人的判断。

所以终局 Pair Vote 如果选出了 A+D，系统最多私下问两个人：

> “要不要多玩一张双人加赛？”

两个人都愿意，才多玩一张**最高4档、无身体接触**的双人题。

这不会自动创建 MATCH，更不会直接给牵手拥抱类内容。

## 11. 第50题不是必须全部跑一遍

每个游戏的50号题是“终局味道”的题，不是说一局必须把7张50号全部玩完。

最后阶段会提高它们的优先级；但真正的最终秘密互选由系统统一执行，所以不会因为随机没抽到某张终局题而漏掉收尾。

## 12. 小局为什么要给 MATCH 降一点权重

4～5人局可配的男女组合本来就少。

如果 MATCH 一出现就给超高优先级，很容易后半场全是同一对，其他人又开始看戏。

所以小局里 MATCH 仍然最强，但不会强到“锁死整桌”；而且 MATCH pair 也照样要遵守冷却轮次。

## 13. 这次还改了哪些题

- 大冒险1～2档换掉约一半“摆姿势 / 模仿”题，加入更像酒吧现场的轻互动。
- “坐到对方旁边”也改成需要对方当前同意，和靠近类规则统一。
- “谁最可能”4档从20张降到16张；4张较轻题移到3档，减少连续 Pair Vote 的重复感。
- 指人游戏4档从19张降到15张；4张较轻的选择移到3档。
- “我从来没有”高档重新统一成“我从来没有……”句式，不再变成普通问答。
- 真心话5档41～49直接在题面写明“两人轮流回答”。
- 二选一私密题不再偷偷参与 Compatibility 累积。
- 默契测试 #40 改回普通公开 Compatibility，不再误当成一次性互相同意。

## 14. 扩圈模式也补完整了

40张扩圈题现在有独立元数据。

陌生人拒绝：立刻切回本桌替代版本，不再邀请第二次。

扩圈永远不参与 MATCH 和 Pair Score，也不索取联系方式、不要求身体接触或饮酒。

## 15. 最后只记6句话

1. 前半场先让所有人参与，后半场才往有火花的人靠。
2. 玩家选5档只是上限，不是马上玩5档。

> **核心职责：** 验证已经形成的连接：让特定两人通过同步选择、猜对方和私密共同选择，判断是否真的合拍。

## 四、发现的问题与改进建议（分级）

### P0-1｜MATCH 触发链路不闭环：5 档内容存在"永远玩不到"的时序风险

**问题**（最重要的一条）：

全库只有 **2 张卡**能创建 MATCH：`PN-NHIE-050`、`PN-POINT-050`（均为 50 号终局卡）。而 40 张 5 档卡（真心话 41–50、大冒险 41–50、二选一 43–50、默契 41–50）全部 `matchRequired=true`，即**必须先有 MATCH 才能出现**。

由此产生两个连锁问题：

1. **触发机制无规格**：00-总览第七节说"进入 H3～H4 后，系统可以在自然节点触发秘密选择"，但这是一句设计意图，没有落成任何规格——触发时机是什么（第几张卡后？H3 达成后多久？）、可否多次触发、系统级秘密互选与两张终局卡是什么关系（是抽这两张卡，还是独立 UI 流程），元数据 notes 与 09"开发最低必须实现"均未定义。抽卡规则（00-总览第九节）只说"剩余合法卡中随机"，**没有终局卡必出保障**。
2. **时序悖论**：若 MATCH 只能靠终局卡形成，则 MATCH 达成时游戏已接近尾声——38 张非终局 5 档卡（双人真心话、牵手/拥抱、MATCH 专属二选一/默契）**几乎没有出场窗口**，5 档体系名存实亡。

另：`PN-MOST-050` 的 postAction = `offer-one-paired-card-if-mutual`（全桌投票选出一对后，若双方愿意则提供一张配对卡）是第三个 MATCH 相关入口，但流程语义同样未定义。

**整改建议**：

1. 在 00-总览新增"秘密互选调度规则"一节：系统级秘密互选从 **H3 中段**（如完成 8–10 张有效卡后）即可首次触发，之后每完成 N 张（建议 5±2）可再次触发；触发方式为系统弹出的私密问题（即总览第七节那句题面），**不依赖任何卡片**。
2. 定义终局卡调度：Session 进入最后 25% 时，保证每游戏 50 号终局卡优先入池（或在结算阶段统一执行），避免终局卡被随机抽卡饿死。
3. 定义 `offer-one-paired-card-if-mutual` 的完整流程：投票结果 → 询问被投双方是否愿意（私密）→ 双方愿意才解锁一张 5 档双人卡；单方不愿意则当无事发生。
4. 明确：MATCH 形成后，该 pair 的 5 档专属回合才进入候选池（现有第九节"5档 70% / 4档 30%"已写，保留即可）。

### P0-2｜扩圈模式 40 张卡没有元数据，fallback 无法实现

**问题**：`10-卡片元数据.json` 只含主线 350 张。扩圈 40 张恰恰是最需要 `fallbackPolicy`（陌生人拒绝 → 立即执行本桌替代版本，不再二次邀请）和 `boundaryTags` 的模块。09 交付范围声称"逐卡开发元数据"，实际扩圈缺失，开发无法可靠实现"拒绝即切换"的硬规则。

**整改建议**：为 40 张扩圈卡补一份精简元数据（可放同一 JSON 或独立 `10b-扩圈元数据.json`），每张至少包含：`cardId / 最低开放度(3|4|5) / responseMode=public / consentMode=skip-anytime / signalEffects=none / fallbackPolicy=switch-to-table-version / boundaryTags=[]`；并注明扩圈卡永不进入 Pair Score 与 MATCH 计算。

### P1-1｜Coverage Gate 的"合格异性互动"无判定标准，H1–H2 可能卡节奏

**问题**：00-总览第三节 Coverage Gate 要求"进入 H3 前每位活跃玩家至少完成 1 次合格异性互动"，但什么算"合格"没有定义——真心话 1–2 档（系统指定异性 + 评论）算吗？大冒险 1–2 档（同步模仿动作，双方未必有定向互动）算吗？谁最可能/二选一（全桌题）显然不算。同时 H1+H2 合计仅约 7 张卡，若其中多张是全桌题，4–5 人局可能出现"卡在 H2 无法进 H3"的节奏停滞。

**整改建议**：在 00-总览明文定义：`targetMode ∈ {system-opposite-sex, choose-opposite-sex, system-pair, signal-pair, match-pair}` 且发生了实际应答/动作的卡 = 合格互动；并在调度规则中加一条下限——**H1–H2 期间每 3 张全桌题至少插入 1 张定向题**（或等价的定向题占比 ≥40%）。

### P1-2｜二选一私密卡参与 Compatibility 计算，与隐私原则有张力

**问题**：`PN-EITHER-041/042`（4 档私密选择）与 `PN-EITHER-050`（终局多选）的 signalEffects 均含 `compatibility`。Compatibility 需要跨题累计（至少 3 道有效共同题），意味着**私密答案要保存到 Session 结束并转为 pair 关系数据**，与总览"原始秘密单选计算后立即丢弃"的精神存在张力，且"散场后继续联系 VS 现在多聊"这类答案被转成关系数据可能超出用户预期。

**整改建议**：二选一私密卡（41/42/50）改为 `signalEffects=[]`，答案仅用于当轮展示；Compatibility 只由公开二选一（1–3 档 + 4 档公开题）计算。

### P1-3｜heatMin / heatMax 字段退化，无信息量

**问题**：脚本实测 350 张卡全部满足 `heatMin = intensity、heatMax = 4`。两个字段完全由 intensity 派生，等于冗余；"H4 时不出现破冰卡"目前只靠抽卡带宽表（软权重）保证，元数据层无硬约束。

**整改建议**（二选一）：

- 方案 A（推荐）：给低档卡设置真实 heatMax——1 档卡 heatMax=2、2 档卡 heatMax=3，让"过热不出破冰题"成为元数据硬约束，与带宽表双保险；
- 方案 B：在 JSON notes 声明"heatMax 恒为 4 是刻意设计，后期降温由带宽表权重控制"，避免开发误读。

### P1-4｜谁最可能 1–3 档个人票去向未定义

**问题**：1–3 档谁最可能是"投一个人"（signals=∅，合理），但"个人得票"是否落库、是否展示历史票型没有说明，开发可能自行发挥。

**整改建议**：在 03-谁最可能执行规则中加一句："1–3 档个人票仅当轮展示、用于气氛，不写入任何关系数据；只有 4 档 Pair Vote 产生 Crowd Signal。"

### P1-5｜大冒险 3 档座位类与靠近类的 consent 判定标准不一致

**问题**：`PN-DARE-019/024`（选人坐到旁边）consentMode=skip-anytime；`PN-DARE-029/030`（面对面渐进靠近/对视）=mutual-current-consent。直觉上"直接坐过去"对个人空间的侵入不弱于"渐进靠近"，两者判定标准相反，开发与玩家都会困惑。

**整改建议**：在 02-大冒险执行规则写明判定标准，例如："座位移动属于公开空间动作（skip-anytime）；面对面靠近、对视 + 距离协商、任何可能进入对方私人距离的动作（mutual-current-consent）"，并按此复核 19/24 是否需要改标签（若认定"坐旁边"=公开动作，现状可保留，但必须写明标准）。

### P2-1｜大冒险 1–2 档全是同步模仿类，酒吧氛围感不足

**问题**：1–2 档共 18 张全部是"同时比数字/摆姿势/模仿动作/镜像"类客厅游戏。破冰有效，但在成年酒吧局里偏幼稚，且与"把语言变成行动、产生关系变化"的玩法职责关联弱（signals=∅ 是对的，但 18 张全空窗使大冒险在半场内对关系引擎零贡献）。

**整改建议**：替换约 1/2（8–10 张）为酒吧场景轻互动：举杯致意并说一句祝酒词（对 TA）、互相用一句话介绍对方给全桌、碰杯时各说一个今晚的观察、并肩看一眼吧台并交换一句评论等。保持无身体接触、1–2 档语义不变。

### P2-2｜4 档高同质库存：指人 19 张、谁最可能 20 张

**问题**：指人 4 档 #31–49 句式几乎全为"指一个……的异性"；谁最可能 4 档 20 张全为"哪两个人……"。单局抽取量下（每玩法约 5–8 张）尚可接受，但语义梯度区分度低（"最想再见 / 最想收到消息 / 最想 MATCH"对被指者几乎等价），连抽两张即有明显重复感。全库 4 档 100 张（28.6%）也使中后段体验密度偏高。

**整改建议**：① 4 档题面做场景锚点改写（散场时 / 明天收到消息时 / 下次见面时——部分已有，扩大覆盖）；② 或结构性压缩：指人 4 档 19→15、谁最可能 4 档 20→16，各补 3–4 张到 3 档，缓解 H3 池深度（3 档现仅 82 张）。

### P2-3｜我从来没有 4 档"今晚限定"脱离玩法句式

**问题**：#41–49 从"我从来没有……"变成"你有没有……"，玩法身份一致性受损（玩家视角变成一般问答）。

**整改建议**：改写回原句式即可，语义不变，例如："我从来没有今晚特别注意过某个人笑起来的样子""我从来没有在游戏还没结束时，就希望散场后还能和某个人继续聊"。

### P2-4｜小局（4–5 人）Pair 路由分差过大

**问题**：4 人局仅 4 个异性 pair、5 人局 6 个。MATCH +5 的 Signal Bonus 在 4 个 pair 的小池中近乎锁死后续配对（次高分 Coverage +3 也追不上），可能出现"剩下半场几乎全是他俩"，与 Coverage Gate 的公平初衷相悖。

**整改建议**：Signal Bonus 按 pair 池规模缩放（如池内 pair 数 ≤6 时 MATCH=+3、Personal=+1），或将 Cooldown 对 MATCH pair 放宽为 3 轮；在 00-总览第八节补一句"小池校准"说明。

### P2-5｜零散小项

| 项 | 位置 | 建议 |
