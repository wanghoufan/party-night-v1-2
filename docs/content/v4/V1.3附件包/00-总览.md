# Party Night V2｜00 总览与统一规则（V1.3 冻结版）

> **唯一基线声明：** 本 V1.3 取代 V1.2 及更早的 V2 / 复核版。进入 SDD 与开发时只能引用本包；旧版本仅作历史存档，不得混用规则或元数据。

## 一、产品目标

Party Night 的主线不是“随机播放 350 张题”，而是让 4～5 人酒吧聚会中的男女关系自然经过：

**破冰 → 注意 → 了解 → 好感试探 → 暧昧 → 双向确认 → 愿意继续认识**

软件负责制造机会、提供第三方借口、控制节奏；**不替玩家决定关系，也不把拒绝设计成失败。**

主线题库：7 种游戏 × 50 张 = **350 张**。`08-扩圈模式.md` 为独立可选的 40 张模块，不计入主线。

### 使用边界

- 当前 V2 按成年人聚会设计；应用本身不要求饮酒。
- 明显醉酒、意识不清或无法稳定表达意愿时，停止 4～5 档、近距离与身体接触任务，切回低档或结束游戏。
- 跳过永远合法：不罚酒、不扣分、不要求解释、不公开是谁拒绝。

## 二、7 种游戏各自只干一件事

| 游戏 | 核心职责 | 主要关系产出 |
|---|---|---|
| 真心话 | 暴露自己的真实判断 | “原来你是这么看我的” |
| 大冒险 | 把语言变成行动、眼神和距离变化 | “我们真的靠近了一点” |
| 谁最可能 | 借全桌视角发现关系信号 | “原来大家也注意到了” |
| 我从来没有 | 发现共同经历与相似行为模式 | “原来你也这样” |
| 二选一 | 快速扫描社交 / 恋爱偏好 | “我们的选择很像 / 很不一样” |
| 指人游戏 | 当前玩家公开做个人选择 | “TA居然选了我” |
| 默契测试 | 验证特定两人的真实合拍度 | “我居然猜中了你” |

**审题最高规则：**一张题如果主要完成的是另一种游戏的职责，应迁移或重写。

## 三、三个概念必须分开：开放度、整桌热度、双人解锁

### 1. Intensity / 开放度：玩家设置的上限

| 档位 | 关系含义 |
|---|---|
| 1 | 注意：开始真正看到对方 |
| 2 | 了解：开始知道对方是什么样的人 |
| 3 | 好感试探：开始让对方知道“我怎么看你” |
| 4 | 暧昧 / 高关系暴露：公开选择、关系判断或明显试探 |
| 5 | 双向确认：需要更明确的双方意愿才能继续 |

档位衡量的是**关系暴露 / 推进程度**，不是身体接触强度。

### 2. Session Heat：整桌当前玩热到哪里，只到 H1～H4

固定总轮数时：

| 进度 | Heat | 内容 |
|---:|---:|---|
| 0～20% | H1 | 破冰、注意 |
| 20～40% | H2 | 了解、共同点 |
| 40～65% | H3 | 主动选择、好感信号 |
| 65～100% | H4 | 明显暧昧、关系试探 |

未设置总轮数时：H1=0～3张，H2=4～7张，H3=8～12张，H4=13张以后。

### 3. Pair Unlock：5档属于具体两个人，不属于整桌

- `matchRequired=true`：只有该 pair 已形成 MATCH 才能进入候选池。
- 一次性双方同意不使用不存在的 `privateMutualRequired` 字段；统一用 `consentMode=private-mutual-only` + `signalEffects=one-off-mutual` 表达，并且只对当轮有效。
- 某一 pair 解锁5档，不代表其他 pair 同时解锁。

## 四、Coverage Gate：先确保每个人都参与，再升温

### 两个数字必须分开：系统给过机会 vs 玩家实际完成

**定向互动机会（offered opportunity）**：系统已经把玩家放进一张明确指向异性 / 双人对象的题里。即使玩家选择跳过，也代表系统已经给过一次公平机会。

**已完成定向互动（completed interaction）**：同时满足：

1. `targetMode` 属于 `system-opposite-sex / choose-opposite-sex / system-pair / signal-pair / match-pair`；
2. 题目实际完成了应答或动作；
3. 不是跳过；
4. 全桌投票、普通二选一、纯聚合统计不算。

跳过只计“系统给过机会”，**不计已完成互动**。这样既尊重跳过，也不会让一个人的连续跳过把整桌的 MATCH 流程锁死。

### H1～H2 的最低调度要求

- 定向题占比不得低于 **40%**。
- 最多连续 2 张全桌题；第 3 张必须优先给定向互动。
- 进入 H3 / 首次 `SYSTEM_MUTUAL_CHECK` 前，每位活跃玩家至少被提供过 1 次合格定向互动机会；是否完成不作为全桌硬门槛。
- 已完成互动次数仍用于公平补偿：系统优先照顾完成次数偏低的人，但**不得因为某人持续跳过而阻止其他人升温或互选**。
- 某玩家连续跳过 2 次定向机会后，可标记为本局 `low-participation`；之后降低主动给 TA 安排定向任务的频率，但 TA 仍可被别人选择，也可随时重新参与。
- 进入 H4 前，系统尽量让非 `low-participation` 玩家完成次数不落后全桌中位数超过 1；这是调度目标，不是锁死 H4 的绝对条件。

男女数量不均衡时按“可获得的合格对象机会数”归一化，不要求绝对相同次数。

## 五、五类关系信号不能混为一谈

1. **Shared**：共同经历。只统计“做过”的少数共同经历；≥80%都做过不加分；“都没做过”不算。
2. **Compatibility**：分两种口径，不能混算。
   - **二选一**：只看公开、信息量足够的共同选择；≥80%全桌共识题和跳过题不计，至少共同回答3道有效题才产生加权。#41/#42/#50 私密答案不参与累计。
   - **默契测试**：看“是否猜中对方”，不是看两个人答案是否一样。1～3档每猜中一个方向记 +0.25 路由证据，单张最多 +0.5，单 pair 全局封顶 +1；#40 若双方偏好相同可记 +0.5。**41～49 已经是 MATCH 专属题，只用于当轮体验，不再继续给 Pair Engine 加 Compatibility，避免正反馈越滚越大。**
3. **Crowd**：全桌对某一 pair 的观察。只有“谁最可能”4档 Pair Vote 产生；不能形成 MATCH。
4. **Personal**：玩家自己公开选择某个异性。单向结果不代表对方也有兴趣。
5. **Mutual / MATCH**：双方分别秘密选择彼此，才形成。

眼神、笑、靠近、模仿等行为**不能自动推断成好感或 MATCH**。

## 六、秘密互选与 MATCH：改成系统级硬流程，不再靠终局卡碰运气

### 第一次秘密互选什么时候出现

满足以下条件后触发系统事件 `SYSTEM_MUTUAL_CHECK`：

- 至少完成 **9 张有效卡**；
- 已进入 H3；
- Coverage Opportunity Gate 已通过：每位活跃玩家至少被提供过 1 次合格定向互动机会；玩家跳过也算“已提供机会”，但不算“已完成互动”。

系统逐个私密询问：

> “今晚到现在，你最想继续了解哪位异性？”

选项：一位当前可选异性 / 暂时没有。

### 后续还会不会再问

- 距离上一次秘密互选至少再完成 **5 张有效卡**，才可再次触发。
- 一局最多 3 次常规秘密互选。
- 如果上次之后出现新的 Personal Signal，优先考虑再次触发。
- Session 结束时始终执行一次最终互选复核；不要求前面的终局卡一定被随机抽中。

### MATCH 怎么生成

- A→D 且 D→A：创建 `MATCH(A,D)`。
- 单向选择：不公开、不起哄，计算完立即删除。
- MATCH 只表示双方愿意继续了解，不是恋爱关系标签，也不是任何身体接触许可。

### MATCH 后如何确保5档真的玩得到

若玩家开放度=5，新 MATCH 形成后：

- 该 pair 的5档卡立即进入候选池；
- 在这对人的**接下来2次合格双人出场机会内**，至少优先安排1张合法5档卡；
- 仍受跳过、当前同意、全桌公平与 cooldown 限制。

这样5档不再依赖 #50 终局卡才有机会出现。

## 七、终局卡与“谁最可能”终局加赛

### #50 终局卡

- #50 是 milestone card，不是唯一的 MATCH 入口。
- Session 最后25%时提高其优先级，但**不强迫一局把7张终局卡全部跑完**。
- Session 真正结束时由系统统一跑最终秘密互选，因此不会因为随机抽不到 #50 而丢掉收尾。

### `PN-MOST-050` 的一次性双人加赛

全桌 Pair Vote 选出一对后：

1. 分别私密询问这两个人：“愿意多玩一张双人加赛吗？”
2. 双方都愿意：只解锁 **1 张**额外双人卡。
3. 该加赛最高4档、`matchRequired=false`，且排除身体接触 / 近距离 / 拍照录像类卡。
4. 它只是一轮 `one-off mutual unlock`，**不创建 MATCH**。
5. 任一方不愿意：当作无事发生，继续游戏；单边答案立即删除。

这样群众起哄只能制造一次机会，不能越权把两个人推进真正5档。

## 八、Pair Engine：先公平，再参考真实信号

`Routing Score = Coverage Score + Signal Bonus - Cooldown Penalty`

它只是“下一轮安排优先级”，**不是爱情概率**。

### 常规权重（可调参）

| 项目 | 权重 |
|---|---:|
| 从未互动过 | +3 |
| 当前玩家曝光明显偏低 | +2 |
| Shared | +0.5 / 次，单pair封顶+1 |
| Compatibility | +0.5 / 次，单pair封顶+1 |
| Crowd | +1 / 次，单pair封顶+2 |
| Personal | +2，封顶+2 |
| MATCH | +5 |
| 上一轮刚配过 | -4 |
| 连续两轮同一对 | -10 |

默认 `Pair Cooldown = 2`。

### 4～5人小局必须自动降权

当当前可用异性 pair 数 ≤6：

- Personal 改为 +1（封顶+1）；
- MATCH 改为 +3；
- Crowd 每次 +0.5（封顶+1）；
- Shared / Compatibility 维持轻权重；
- MATCH pair 也不能绕过 cooldown。

目标：防止一个 MATCH 出现后，后半场几乎只剩这一对在玩。

## 九、抽卡规则与 heatMax 硬边界

V1 的 `INTENSITY_WEIGHT = 1 / 2 / 4 / 8 / 16` 作废。

V2 顺序：开放度 → Session Heat → 目标对象 → 逐卡元数据过滤 → Coverage/Cooldown → 合法卡中随机。

### heatMin / heatMax 不再是冗余字段

- 1档：`heatMin=1, heatMax=2`，H3以后硬性退出候选池。
- 2档：`heatMin=2, heatMax=3`，H4退出候选池。
- 3档：`heatMin=3, heatMax=4`。
- 4档：`heatMin=4, heatMax=4`。
- 5档：`heatMin=4, heatMax=4`，同时还必须满足 pair 解锁条件。

因此后半场不会靠“软概率”大量抽回破冰题。

### Heat 内仍保留轻量抽卡带宽

`heatMax` 负责“哪些卡绝对不能再出现”，带宽负责“同一 Heat 内哪一档更常出现”。两者同时生效。

| Session Heat | 合法卡默认权重 |
|---|---|
| H1 | 1档 100% |
| H2 | 2档 80% / 1档 20% |
| H3 | 3档 75% / 2档 25% |
| H4 | 4档 60% / 3档 30% / 5档 10%（仅当前 pair 已解锁5档时） |

- 如果 H4 当前 pair 没有合法5档，剩余 4档 / 3档按原比例重新归一化。
- **MATCH pair 的专属双人回合**：5档 70% / 4档 30%；仍需满足逐卡同意与边界规则。
- “新 MATCH 后 2 次合格机会内至少安排 1 张5档”是最低保障；70/30 是专属回合内的内容节奏，两者并不冲突。
- 某玩法当前没有目标档位合法卡时，回退到最近的合法较低档位，而不是越权放出更高档。

## 十、同意与拒绝统一规则

1. 任意玩家随时可跳过；不罚酒、不扣分、不解释。
2. 身体接触、移动座位到对方身边、持续对视、进入更近谈话距离、拍照/视频，都必须当前再次确认。
3. 同意牵手不等于同意拥抱；已同意也可随时停止。
4. 拒绝后不得换成“轻一点再问一次”的连续施压。
5. MATCH 不是任何身体接触默认许可。
6. 双方秘密选择动作时只执行交集；无交集就跳过，不自动替换另一个动作。

## 十三、扩圈模式

- 默认关闭；开放度3～5才可见。
- 不计入 MATCH、Pair Score 或主线关系阶段。
- 不要求陌生人身体接触，不索取联系方式，不要求饮酒。
- 对方拒绝或场景不合适：立即执行本桌 fallback，不二次邀请。
- 40张逐卡规则见 `10b-扩圈元数据.json`。

---

## 十四、最终产品循环

**公平破冰** → **共同经历 / 偏好发现** → **主动选择** → **全桌观察** → **系统级秘密互选** → **MATCH** → **该 pair 解锁5档** → **每个具体动作再次确认** → **双方自己决定是否继续认识**

最终原则：

> **软件制造机会，但不替任何人做决定；算法提高相遇机会，但不制造假的好感。**
