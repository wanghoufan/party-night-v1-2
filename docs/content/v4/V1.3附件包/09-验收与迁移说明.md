## 二、本轮针对第三方报告完成的整改

### P0 全部完成

1. **MATCH 触发链路闭环**：新增系统级 `SYSTEM_MUTUAL_CHECK`，首次在≥9张有效卡、H3且Coverage Gate通过后触发；之后至少间隔5张有效卡，常规最多3次；Session结束必做最终复核。MATCH后开放度=5时，在该pair接下来2次合格双人机会内优先安排至少1张合法5档卡。
2. **扩圈40张补元数据**：新增 `10b-扩圈元数据.json`，逐卡定义 `fallbackPolicy=switch-to-table-version`，并明确不进入Pair Score与MATCH。

### P1 全部完成

3. 定义“合格异性互动”与H1～H2定向题比例下限40%，最多连续2张全桌题。
4. `PN-EITHER-041/042/050` 退出 Compatibility 累积。
5. heatMax 改成真实硬边界：1档≤H2、2档≤H3、3～5档≤H4。
6. 谁最可能1～3档个人票只当轮展示、不落库；仅4档Pair Vote产生Crowd。
7. 大冒险座位移动与靠近规则统一：移动到对方身边也要求当前双方同意。

### P2 全部处理

8. 大冒险1～2档替换9张为更贴酒吧现场的轻互动。
9. 谁最可能4档20→16、指人4档19→15；较轻内容移到3档，并重写高档场景锚点，减少连续重复感。
10. 我从来没有41～50统一恢复“我从来没有……”玩法句式。
11. 4～5人小局新增Signal Bonus降权，防止MATCH pair垄断后半场。
12. `PN-CHEM-040` 改为公开 Compatibility；真心话5档41～49题面明确“两人轮流回答”。

## 三、额外修正（报告未明确列出）

- 删除文档层不存在于JSON的 `privateMutualRequired` 伪字段；一次性双方同意统一用 `consentMode=private-mutual-only + signalEffects=one-off-mutual` 表达。
- `PN-MOST-050` 不允许“群众投票→直接5档”。改为双方私密同意后只加赛1张最高4档、无身体接触的双人卡，不创建MATCH。
- #50终局卡定义为 milestone card；最后25%提高优先级，但不强迫7张全部出现。真正的最终互选由Session结算统一保证。

## 四、V1.3 根据独立复审追加的边界修复

1. **Coverage Gate 改为“机会门槛”**：每位活跃玩家被提供过至少1次合格定向互动机会即可满足 H3 / `SYSTEM_MUTUAL_CHECK` 的公平门槛；玩家跳过不算完成互动，但不能锁死全桌 MATCH。连续跳过2次可标记 `low-participation`，降低主动定向频率但仍保留被选择与重新参与权利。
2. **恢复 Heat 抽卡带宽**：H3 以3档为主，H4 以4档为主；合法 MATCH pair 才能混入5档；专属 MATCH 回合采用5档70% / 4档30%。`heatMax` 继续作为硬边界。
3. **默契 Compatibility 口径收敛**：1～3档按猜中对方产生轻量证据，#40 按偏好一致；#41～49 已是 MATCH 专属，不再继续给 Pair Engine 加权。
4. **版本唯一化**：V1.3 取代 V1.2 与旧 V2；本包新增版本冻结说明，旧版本不得参与开发。

## 五、V1 / 旧V2迁移必须删除

- `INTENSITY_WEIGHT = 1/2/4/8/16`
- “4～5档固定占70%”
- 全桌H5
- 用群众判断或单向选择生成MATCH
- 无共同同意时自动换动作
- 私密二选一长期参与Compatibility
- 把“都没做过”计Shared
- DOUBLE MATCH
- 秘密单向结果长期保存

## 六、开发最低必须实现

1. Intensity 1～5；Session Heat H1～H4。
2. Coverage Gate + H1/H2定向题比例控制。
3. 系统级秘密互选调度，不依赖随机终局卡。
4. MATCH pair 5档解锁与“2次机会内优先出1张”的保障。
5. Pair Cooldown + 小局Signal降权。
6. 私密选择只显示共同结果，单向结果立即删除。
7. 动作级current consent。
8. Shared / Compatibility / Crowd / Personal / Mutual 分离。
9. One-off Mutual 与 MATCH 分离。
10. 扩圈独立开关 + `10b` fallback元数据。
11. Session结束清理敏感关系状态。
