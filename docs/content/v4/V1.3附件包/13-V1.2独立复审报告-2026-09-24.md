## 五、本轮复审新发现的问题（V1.2 残留）

### P1-新1｜Coverage Gate 无降级路径：一个连续跳过的玩家会锁死全桌的 MATCH

**问题**：`SYSTEM_MUTUAL_CHECK` 的触发条件之一是"Coverage Gate 已通过"（每位活跃玩家至少 1 次合格异性互动）。但若某位玩家性格内向或状态不佳，连续跳过所有定向题，该条件永远无法满足——而规则中的"在数学上可行时"只覆盖性别比例等结构性不可行，不覆盖行为性不可行。后果：**一个人的跳过行为会阻止其他所有 pair 的 MATCH 触发**，直到 Session 结束的最终兜底互选为止，这违背了"跳过不惩罚"的本意（跳过者不应被惩罚，但也不应连累他人）。

**整改建议**（任选其一，建议 A）：

- A：Gate 按"机会而非完成"计——系统为每位玩家提供过 ≥1 次定向题机会（无论是否跳过）即视为该玩家侧条件满足；
- B：设松弛阈值——有效卡数达到 N（建议 12）后，Gate 未通过也允许触发秘密互选，并在 notes 记录该 Session 为"低参与局"；
- C：Gate 改为"除明确连续跳过者外其余玩家均完成"，跳过者本人仍保留被他人选择的权利。

### P2-新1｜抽卡带宽表被整体移除，H4 升温曲线变平

**问题**：v2 版 00-总览第九节曾有默认抽卡带宽表（H4：4 档 70% / 3 档 25% / 2 档 5%）与 MATCH pair 专属回合"5 档 70% / 4 档 30%"。V1.2 用 heatMax 硬边界取代了带宽表，但硬边界只负责"不让破冰题回场"，**不负责"让高档题优先"**。脚本实测 H4 合法池构成：3 档 90 张 + 4 档 92 张（+ 已解锁 5 档），均匀随机下后半场约一半抽到 3 档题，暧昧段密度低于 v2 设计意图；MATCH pair 的 5 档优先也从"70% 权重"弱化为"2 次机会内优先安排 1 张"。

**整改建议**：在 00-总览第九节补回轻量带宽（与 heatMax 双保险）：H3 = 3 档 75% / 2 档 25%；H4 = 4 档 60% / 3 档 30% / 5 档（若该 pair 已解锁）10%；MATCH pair 专属回合恢复 5 档 70% / 4 档 30%。若团队确认"均匀随机是刻意设计"，则请在 notes 中显式声明，避免开发期误读。

### P2-新2｜默契测试 41–49 的 Compatibility 计入语义未定义

**问题**：脚本实测 CHEM-041~049 均带 `signalEffects=[compatibility]`（40 张 compatibility 卡 = 二选一 47 + 默契 40 中的一部分）。但 JSON notes 与 00-总览只定义了**二选一**的 Compatibility 口径（同答案、≥80% 共识排除、≥3 道有效题）；默契测试的 Compatibility 是"猜中对方"而非"答案相同"，两套口径不同：猜中率怎么折算加权？是否同样封顶 +1？80% 共识规则是否适用？均未写明。

**整改建议**：在 JSON notes 补一条默契 Compatibility 口径，例如"每双向猜中一次 +0.5，单 pair 封顶 +1；仅统计双方都完成揭晓的题"；或保守起见将 CHEM-041~049 的 compatibility 移除（该阶段 pair 已 MATCH，路由权重本就不缺）。

### P2-新3｜版本管理：v2 旧文件夹与 v3（V1.2）并存，需明确唯一基线

**问题**：当前 `docs/content/` 下 v2（复核优化版，含本复审报告）与 v3（V1.2 最终优化版）并存，两者内容已有实质差异（档位分布、题面、元数据 schema 2.2）。开发若误读 v2 会拿到旧规格。

**整改建议**：冻结时在 v2 文件夹顶部（00-总览首行或新增一行 README 式说明）标注"本版本已被 `../v3/` V1.2 取代，仅作历史存档"；SDD 与开发只引用 v3。
