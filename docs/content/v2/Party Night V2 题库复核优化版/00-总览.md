# Party Night V2｜00 总览与统一规则（复核优化版）

## 一、产品目标

Party Night 的主线不是“随机播放 350 张题”，而是让 4～5 人酒吧聚会中的男女关系自然经过：

**破冰 → 注意 → 了解 → 好感试探 → 暧昧 → 双向确认 → 愿意继续认识**

软件负责制造机会、提供第三方借口、控制节奏；**不替玩家决定关系，也不把拒绝设计成失败。**

主线题库：

- 7 种游戏 × 50 张 = **350 张**
- 01 真心话
- 02 大冒险
- 03 谁最可能
- 04 我从来没有
- 05 二选一
- 06 指人游戏
- 07 默契测试

`08-扩圈模式.md` 是独立可选模块，不计入 350 张主线。

### 使用边界

- 当前 V2 按**成年人聚会**设计；应用本身不要求饮酒。
- 如涉及酒精饮品，应遵守当地法律与场所规则。
- 如果任何人已经明显醉酒、意识不清、无法稳定表达意愿，应停止 4～5 档和身体接触类任务，切回低档或结束游戏。

## 二、7 种游戏的职责必须互不替代

| 游戏 | 唯一核心职责 | 主要关系产出 |
|---|---|---|
| 真心话 | 暴露自己的真实判断 | “原来你是这么看我的” |
| 大冒险 | 把语言变成行动、眼神和距离变化 | “我们真的靠近了一点” |
| 谁最可能 | 借全桌视角发现关系信号 | “原来大家也注意到了” |
| 我从来没有 | 发现共同经历和相似行为模式 | “原来你也这样” |
| 二选一 | 快速扫描社交 / 恋爱偏好 | “我们的选择很像 / 很不一样” |
| 指人游戏 | 当前玩家公开做个人选择 | “TA居然选了我” |
| 默契测试 | 验证特定两人的真实合拍度 | “我居然猜中了你” |

### 审题最高规则

一张题如果主要完成的是另一种游戏的职责，应迁移或重写。

- 二选一里“选完立刻拥抱” → 应属于大冒险。
- 谁最可能投完后强迫得票者讲秘密 → 应属于真心话。
- 我从来没有后接“没做过的现在做一次” → 应属于大冒险。
- 指人游戏变成全桌投票 → 应属于谁最可能。
- 默契测试只让两个人各做一次普通二选一 → 与二选一重复，应改成“先猜对方再揭晓”。

## 三、Intensity、Session Heat、Pair Unlock 必须分开

### 1. Intensity / 开放度：玩家控制的天花板

玩家开局只操作现有 1～5 档。

| 档位 | 关系含义 |
|---|---|
| 1 | 注意：开始真正看到对方 |
| 2 | 了解：开始知道对方是什么样的人 |
| 3 | 好感试探：开始让对方知道“我怎么看你” |
| 4 | 暧昧 / 高关系暴露：出现公开选择、关系判断或明显试探 |
| 5 | 双向确认：需要更明确的双方意愿才能继续 |

**档位衡量关系暴露 / 推进程度，不等于身体接触强度。**

因此：

- “和异性击掌”可能只有 1～2 档。
- “如果今晚只能继续联系一个异性，你选谁”可以是 4 档。
- 5 档不要求每种玩法都必须有；例如“谁最可能”只产生群众判断，因此可以自然止步于 4 档。

### 2. Session Heat：整桌当前节奏，只到 H1～H4

V2 不再把 H5 当成全桌状态。原因：一桌里可能只有某一对已经互选，其他人并没有进入同样的关系阶段。

如果开局设置了固定总轮数，可按整局进度：

| 整局进度 | Session Heat | 主要内容 |
|---:|---:|---|
| 0～20% | H1 | 破冰、注意 |
| 20～40% | H2 | 了解、共同点 |
| 40～65% | H3 | 主动选择、好感信号 |
| 65～100% | H4 | 明显暧昧、关系试探 |

如果没有设置总轮数，默认按已完成有效卡数：

- H1：0～3 张
- H2：4～7 张
- H3：8～12 张
- H4：13 张以后

### 3. Coverage Gate：先保证参与，再升温

仅靠轮数不够。系统还要检查曝光公平性：

- 在数学上可行时，进入 H3 前，每位活跃玩家至少完成过 1 次合格异性互动。
- 进入 H4 前，任何人的“有效互动次数”不应落后全桌中位数超过 1；若落后，先做低曝光补偿。
- 男女数量不均衡时，按“可获得的合格对象机会数”归一化，不追求绝对相同次数。

### 4. Pair Unlock：5档是“某一对”的权限，不是全桌 Heat

5档卡通过逐卡条件解锁：

- `matchRequired = true` → 只有该 pair 已形成 MATCH 才能出现。
- `privateMutualRequired = true` → 当前双方秘密同意后，只解锁本次动作 / 卡片，不自动形成 MATCH。

因此：

**Session Heat = 1～4；5档 = pair-specific unlock。**

## 四、Relation Stage：每张卡自己的任务

推荐统一枚举：

- `notice` 注意
- `know` 了解
- `signal` 好感信号
- `flirt` 暧昧试探
- `continue` 愿意继续关系

Relation Stage 是“这张卡结束后，希望产生什么关系结果”，与 Intensity 不完全相同。

---

## 五、男女互动局的目标对象规则

当前 V2 主场景为“男女互动局”。

- 1～2档关系题：系统优先指定异性，减少总挑安全对象的情况。
- 3～4档：允许玩家主动选择异性，形成 Personal Signal。
- 5档：只按逐卡双向条件解锁。
- 同性仍可参与全桌协作、投票和公共题，但不作为男女关系推进题的默认目标。

### 开局有效性检查

- 男女互动局至少需要存在 1 组可用异性 pair。
- 性别信息只用于当前 Session 的目标池与配对，不应持久保存。
- 后续如扩展其他关系偏好，应另做 `targetPool` 配置；当前 V2 不混入额外复杂度。

## 六、关系信号：语义强度与路由权重不要混为一谈

### 1. Shared Signal

来自“我从来没有”等共同经历。

- 只统计选择“做过”的共同经历；“两个人都没做过”不算共同经历。
- 当 80% 以上玩家都“做过”时，该题信息量过低，不计配对加权。
- 高档“今晚有没有某个人”类私密题不产生 Shared Pair Signal。

### 2. Compatibility Signal

来自二选一 / 默契测试。

- 全桌二选一中，当一个选项被 80% 以上玩家选择时，不计兼容加权。
- 排除跳过与低信息量题。
- 至少共同回答 3 道有效题，才允许产生 Compatibility 加权。

### 3. System Signal

来自系统事实：

- 是否从未互动
- 互动次数是否偏少
- 是否刚刚连续配过
- 当前 Session 的曝光公平性

### 行为线索不自动等于好感

对视、笑、靠近、模仿等行为可以作为游戏互动内容，但系统**不能把这些行为自动推断成“喜欢”或 MATCH**。它们最多属于一次 Session Event；真正的 Personal / Mutual Signal 必须来自玩家自己的明确选择。

### 4. Crowd Signal

来自“谁最可能”的 Pair Vote。

- 只说明全桌观察到两人有某种外部信号。
- Crowd Signal 不能形成 MATCH，也不能触发身体任务。

### 5. Personal Signal

来自真心话主动选择、指人游戏、主动选搭档等。

- 单向 Personal Signal 不公开为“对方也喜欢你”。
- 主动选择永远允许跳过，系统不得为了凑信号强迫用户选一个人。

### 6. Mutual Signal / MATCH

只有双方分别秘密选择彼此，才形成 MATCH。

MATCH：

- 是 Session 内的 pair-level 状态。
- **不是恋爱关系标签，也不是排他关系。**
- 同一玩家在不同时间点可以和不同对象形成 Session MATCH；系统不得把 MATCH 解读成“已经配对成功”。
- 只代表双方在那个时点都愿意继续了解彼此。

### 7. One-off Mutual Unlock

某些卡只需要“这一次双方都愿意”，例如解锁一张双人卡。

它：

- 不进入长期 Pair Score；
- 不创建 MATCH；
- 不保存单边选择；
- 本轮结束后失效。

## 七、秘密互选与 MATCH

进入 H3～H4 后，系统可以在自然节点触发秘密选择：

> “今晚到现在，你最想继续了解哪位异性？”

选项：

- 一位异性
- 暂时没有

系统只计算双向结果：

- A → D 且 D → A → `MATCH(A,D)`
- A → D 但 D → B → 什么都不公开

### 隐私原则

- 单向选择不公开。
- 单向选择不用于当众起哄。
- 高关系私密回答只显示双方共同结果。
- 原始单向答案完成本轮计算后立即丢弃，不写入长期历史。

### MATCH 不等于身体接触同意

MATCH 只表示双方都愿意继续了解彼此。任何牵手、拥抱、触碰、近距离任务、拍照等行为，都必须在**当前动作发生前再次确认**。

---

## 八、Pair Engine：先公平，再根据真实信号收敛

不要把 Pair Score 当作“喜欢概率”。它只是**这一轮该不该让两个人再次互动的路由分**。

建议拆成：

`Routing Score = Coverage Score + Signal Bonus - Cooldown Penalty`

### Coverage Score

| 条件 | 示例权重 |
|---|---:|
| 从未互动过 | +3 |
| 当前玩家曝光明显偏低 | +2 |

### Signal Bonus（建议封顶）

| 信号 | 示例加权 |
|---|---:|
| Shared 有效命中 | +0.5，单 pair 最多 +1 |
| Compatibility 有效命中 | +0.5，单 pair 最多 +1 |
| Crowd Signal | +1，单 pair 最多 +2 |
| Personal Signal | +2，单 pair 最多 +2 |
| MATCH | +5 |

### Cooldown

| 条件 | 示例权重 |
|---|---:|
| 上一轮刚配过 | -4 |
| 连续两轮同一对 | -10 |

默认：`Pair Cooldown = 2`

### 防止“越热门越热门”

- Shared / Compatibility / Crowd 的加权必须封顶。
- Crowd Vote 可以继续真实显示，但不能无限叠加路由优势。
- 系统配对可做低曝光补偿；**不能篡改用户自己的 Personal Choice。**

## 九、抽卡规则

V1 的：

`INTENSITY_WEIGHT = 1 / 2 / 4 / 8 / 16`

在 V2 中作废。

V2 顺序：

1. 读取玩家开放度 Intensity。
2. 读取 Session Heat H1～H4。
3. 读取本轮目标 pair / target。
4. 按逐卡元数据过滤 `heatMin / heatMax / targetMode / matchRequired / consentMode`。
5. 应用 Pair Cooldown 与曝光公平规则。
6. 在剩余合法卡中随机。

### 5档规则

- 5档不会因为“整局时间到了”自动出现。
- 只有逐卡双向条件成立时才进入候选池。
- 某一 pair 解锁5档，不代表全桌其他 pair 也进入5档。

### 默认抽卡带宽

合法卡过滤完成后，再按当前 Heat 给相邻档位不同权重，避免 H4 时仍大量抽到破冰题：

| Session Heat | 默认库存权重 |
|---|---|
| H1 | 1档 100% |
| H2 | 2档 80% / 1档 20% |
| H3 | 3档 75% / 2档 20% / 1档 5% |
| H4 | 4档 70% / 3档 25% / 2档 5% |

如果当前选中的 pair 已解锁5档且玩家开放度为5，则该 pair 的专属回合可优先：**5档 70% / 4档 30%**。某玩法没有对应档位时，回退到最近的合法较低档位。

## 十、同意与拒绝统一规则

以下规则对所有玩法生效：

1. 任意玩家随时可以跳过。
2. 跳过不罚酒、不扣分、不要求解释。
3. 不公开是谁拒绝了高关系选项。
4. 身体接触、明显进入私人距离、拍照 / 视频都必须当前再次明确同意。
5. 同意必须针对当前具体动作；同意牵手不等于同意拥抱。
6. 已经同意也可以随时改变主意并停止。
7. 拒绝一次后，本轮不得换成“轻一点再问一次”的连续施压。
8. MATCH 不是任何身体接触的默认许可。
9. 明显醉酒、意识不清或无法清晰表达意愿时，不进入高档身体 / 距离任务。
10. 主线不设计露骨性动作、不涉及身体隐私部位、不通过灌酒推动互动。

### 无共同选择时的 fallback

所有“双方秘密选择可接受动作”的题：

- 只执行双方选择的交集；
- 没有交集 → **直接跳过动作 / 继续聊天**；
- 不得系统自动换成另一个未经双方选择的动作。

## 十一、卡片数据结构：必须真正落到每一张卡

只有“推荐字段”但不给逐卡元数据，开发者无法可靠实现路由。因此 V2 复核版要求每张卡至少具备：

```text
schemaVersion
cardId
gameType
intensity
heatMin
heatMax
relationStage
targetMode
responseMode
interactionType
consentMode
matchRequired
signalEffects
postAction
boundaryTags
fallbackPolicy
```

推荐 `targetMode`：

- `system-opposite-sex`
- `choose-opposite-sex`
- `pair-vote`
- `system-pair`
- `signal-pair`
- `match-pair`
- `all-players`
- `private-choice`

推荐 `responseMode`：

- `public`
- `aggregate-only`
- `private-individual`
- `private-mutual-result`

推荐 `consentMode`：

- `skip-anytime`
- `mutual-current-consent`
- `private-mutual-only`

推荐 `signalEffects`（数组，可同时产生多个效果）：

- `none`
- `shared`
- `compatibility`
- `crowd`
- `personal`
- `mutual-match`
- `one-off-mutual`

逐卡元数据见同包 `10-卡片元数据.json`。

**题面只放玩家应该看到的内容；“只显示交集 / 不形成 MATCH / 计算后删除”等实现规则放在元数据和总纲，不应直接显示在游戏卡片上。**

## 十二、隐私与数据生命周期

Party Night 会处理“谁选择谁、谁愿意继续认识谁”等高敏感社交信息，因此默认采用数据最小化：

- 玩家显示名、性别目标池、Pair Signal 只服务当前 Session。
- 原始秘密单选不写入持久历史；计算出双向结果后立即删除。
- 默认不把 Pair Signal、MATCH、私密答案发到云端分析或第三方统计。
- Session 结束时清空关系图、秘密答案和 MATCH 状态。
- 若未来要提供“保存战绩”等功能，必须把它设计成单独、明确的用户选择，而不是默认保存。

## 十四、扩圈模式

旧稿中的“酒吧陌生人挑战”不混入主线 350 张。

- 默认关闭。
- 玩家主动开启后，40 张扩圈卡才进入候选池。
- 仅开放度 3～5 可见。
- 不计入 MATCH。
- 不要求陌生人身体接触。
- 不索取联系方式。
- 任何拒绝立即结束该尝试，不进行二次邀请。

详见 `08-扩圈模式.md`。

## 十五、最终产品循环

**系统轮换异性破冰**
→ **共同经历 / 偏好发现**
→ **玩家开始主动选择**
→ **全桌观察到信号**
→ **系统在公平基础上增加高信号组合互动**
→ **秘密互选**
→ **PAIR-SPECIFIC MATCH**
→ **该 pair 解锁5档内容**
→ **每个具体动作再次确认**
→ **双方自己决定今晚之后是否继续**

最终原则：

> **软件制造机会，但不替任何人做决定；算法提高相遇机会，但不制造假的好感。**
